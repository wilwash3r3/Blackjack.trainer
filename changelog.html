v0.51.0Current

Wired the trainer into the series. The start screen's footer now links to the front door (`index.html`) and carries the same series rail the landing pages use, with the current game marked and the Blackjack trainer one click away. Because each game lives in its own repository, the cross-link is a sibling path — on GitHub Pages the two sites sit side by side under the same domain, so `../Blackjack.trainer/` resolves without hardcoding a full URL.

v0.50.0

You can step away mid-hand now. The whole table persists — the remaining deck in its exact order, the board, every stack and side-pot contribution, folded and all-in state, the dealer button, the blind level, each AI's read on you, and the full tournament or multi-table structure around it — so the start screen offers Resume Table and tells you exactly what's waiting ("tournament, level 4, hand #38 (turn)"). It resumes rather than reconstructs, which is the only version of this worth shipping: reconstruction is what would quietly corrupt the odds. The one thing not restored is whichever AI was mid-think when you left, since its timer died with the page — that player just takes its turn again. New Game discards the saved table, so a fresh start stays fresh.

v0.49.0

Stopped the cards flashing. Every action rebuilds the table's markup, and the deal animation was attached to every card unconditionally, so all of them replayed it on every AI decision. Cards now animate only the first time they actually appear — the render remembers what was already on screen and animates just the new ones. And "Continue Saved Game" was overpromising. It never restored a table or tournament in progress; it restores what you've learned and earned. It's now called Continue Progress, the start screen says in plain terms what does and doesn't carry over, and a new Manual section explains why a mid-hand resume isn't there: doing it wrong would quietly corrupt the odds you're being trained on, which is worse than dealing a fresh table.

v0.48.3

Made the unrolled menu actually clickable. Closing was driven by mouseleave, which is the wrong signal here: the row animates in underneath the moving cursor, and any moment the pointer spent in the gap between the logo and a tab started a countdown to collapse — so the thing you were aiming at kept rolling away. Opening is still hover; closing now depends on where the pointer actually is, and only happens once you've moved clearly below the whole header block with a 90px grace margin.

v0.48.2

The card preview no longer disappears behind the header. v0.48.1

Fixed the table fit properly. Two real bugs behind the jumping. First, the chrome height was measured by subtracting the table's already-scaled height from its container, so the measurement ate its own tail: the smaller the table got, the larger "chrome" appeared, the available height walked toward zero, and the scale collapsed to its floor no matter how much room was genuinely free — which is also why rolling the chrome up never actually grew the table. The chrome is now measured with the table's slot collapsed to zero, so the freed space converts into scale as intended. Second, the scale was applied a frame after the DOM was replaced, so the table painted unscaled at full size for one frame on every render — a flash-and-snap on each AI action. The cached scale is now stamped into the markup itself, so the first painted frame is already correct.

v0.48.0

Two fixes. The table stopped jumping around. Its scale was re-derived from the measured chrome height on every single render, and that height changes constantly mid-hand as the action row rewraps and the hand log fills up — so the table resized in response to ordinary play. The log now has a fixed cap instead of a computed one (it can't feed back into the measurement), and a new scale has to differ by a real margin before it's applied; genuine layout changes — a window resize, the chrome rolling up or down — still force an exact re-fit. And busting out of a tournament no longer traps you in spectator mode: the status bar now offers "Start New Tournament" (or "Back to Career") the moment you're out, with the old Abandon button relabelled "Stop Spectating".

v0.39.0

Tackled the last item: mobile responsiveness. Read Blackjack's actual 28 media queries directly rather than guessing at patterns, and ported the single most important one: below 480px width, the poker table's absolutely-positioned oval arc of seats — which doesn't have room to exist at phone width no matter how small the text gets — is abandoned entirely in favor of a plain vertical list, the exact same structural fix Blackjack's own table uses at the same width for the same reason. This was more than a copy-paste: Hold'em's seat positions are set by inline style="left:...; top:..." attributes from JS, and CSS specificity gives inline styles priority over any selector unless marked !important — so the override needed !important on position, left, top, and transform simultaneously, which a normal media-query rule wouldn't have achieved. Also disabled the seat-pulse animation on this layout rather than trying to make it behave: the animation's keyframes bake in a translate(-50%,-50%) centering transform that no longer applies once seats are static, and CSS animations can silently override an !important transform declared elsewhere for the same property — sidestepping that fight entirely by swapping to a plain static highlight was simpler and more reliable than trying to win it. Beyond the table: hid keyboard-shortcut badges and disabled hover-only tooltips under (pointer:coarse) since neither means anything without a keyboard or a mouse, bumped every button to a real 44px touch target (the standard floor on both iOS and Android — the desktop padding alone fell short), and added tablet and phone breakpoints scaling down text, cards, and spacing across the tabs most likely to feel cramped (Range Reading's grid, Career's tier table, the Skills Test). Tested everything that's actually testable without a real browser: confirmed the seat override rule genuinely carries !important on all four properties that need it, confirmed the touch button rule hits the real 44px floor, confirmed key-badges are hidden under the coarse-pointer query, confirmed the animation is disabled rather than left to conflict, confirmed the stylesheet itself has balanced braces, and reran the full 36,000-hand regression plus a 13-tab render sweep to confirm none of this — being CSS-only — touched any actual game logic. What I could not do, and want to be direct about rather than imply otherwise: none of this has been seen on an actual phone or in an actual browser. I can verify the right rules exist with the right specificity; I can't verify how it actually looks without the ability to render and screenshot a real page, which isn't available here. That's a real gap between "structurally correct" and "confirmed to look right," and it's the honest place to end this pass.

v0.38.0

Added the EV & Risk Calculator, the single biggest remaining feature gap versus Blackjack's own EV tab: a new 13th tab computing Risk of Ruin, N₀, and a session variance range against the real career bankroll economy. The interesting design problem here was where the variance number should even come from — real published tournament-variance figures exist, but every one I found is calibrated to 500-2000+ player professional-circuit fields, nothing like this trainer's own 6/9/72/90-player tiers, so importing one of those numbers directly would have been quietly dishonest despite looking authoritative. Instead, variance is derived analytically from the trainer's own real, already-tested payout structure: a skill-tilt parameter is calibrated by binary search so the mean profit exactly matches whatever ROI% the player states, and that same calibrated distribution is then used to compute variance — internally consistent by construction rather than two mismatched numbers bolted together. From there, Risk of Ruin and N₀ use the identical diffusion-approximation formulas already proven out in Blackjack's own EV tab, just applied to per-tournament units instead of per-hand. A "Use My Current Career Numbers" button pulls your real bankroll, current tier's buy-in, and actual field size (the real one, if you're mid-tournament, not a guess) directly from live career state. Caught a real bug before it ever reached testing: an early version referenced a constant that's declared later in the file, which throws in JavaScript since const isn't hoisted the way function is — caught immediately by the syntax/reference check that runs before any test is allowed to proceed. Tested extensively given how much new math this introduces: confirmed the skill-tilt calibration hits the exact stated ROI (within 5 cents) across 25 combinations of field size and target ROI, confirmed variance is never negative and correctly increases with field size at a fixed ROI (a real, well-known property of tournament variance), confirmed Risk of Ruin's edge cases (zero bankroll means certain ruin, a losing player means certain ruin regardless of bankroll, zero variance with a positive edge means zero risk, and more bankroll always lowers risk at fixed mean/variance), confirmed N₀ correctly requires more events for a weaker edge, confirmed the career-numbers button pulls genuinely live data including the real active tournament's field size when one is in progress, and a full persistence round-trip for every input. The calculator's own disclosed assumptions (a smooth parametric model, no stake adjustment in the Risk of Ruin math) are stated directly in the tool itself, not just in this changelog. Full 24,000-hand regression and a 13-tab render sweep came back clean.
